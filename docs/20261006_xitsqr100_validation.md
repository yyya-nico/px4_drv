# XIT-SQR100 の Linux 実機調整と検証

検証環境は Linux x86_64、カーネル `7.0.0-34-generic`、gcc-13、recisdb `1.2.4`、USB 接続の XIT-SQR100 です。利用者の申告では地デジと BS/CS の両方が接続されています。カード配置は未確認で、全受信試験は `--no-decode` による生 TS が対象です。検証日は2026年10月6日です。

今回の変更で、デバイス open 時の SLVT bank 0 select の I²C エラーは解消し、地デジ・BS・CS の選局と受信を確認できました。ただし、地デジの開始直後には TEI と形式不正が残っているため、長時間録画向けの受信対応が完成したという判断には至っていません。

## 原因の照合と修正範囲

| 条件 | 変更前 | 変更後と根拠 |
|---|---|---|
| FREIA のフラグ `0x10004000` | `0x4000` を IF 出力制限として解釈し、REFOUT は無効 | Sony 参照定義の `REFOUT_800mVpp` に訂正。register `0x84 = 0x83` は Windows キャプチャとも一致 |
| IF 出力制限 | `outlmt_dtv_1_2vpp = true` | false。参照定義の当該フラグは `0x40000` で、キャプチャの register `0x68` は `0x00` |
| IT930x の TS 入力 | 未確認の port 4 | serial TS の port 0。キャプチャの `0xda58 = 0`、`0xda73 = 1`、`0xda4c = 1` と一致。無効入力の port 番号も1〜4へ分離 |
| CXD2856ER の TS clock | PXMLT の従来値を使用 | 機種設定で Windows と同じ clock を選択。PXMLT の Linux/WinUSB は新設定を明示的に無効化して従来値を維持 |
| 地デジ・衛星の方式判別 | 初期状態を地デジへ固定し、BS01_0 は EINVAL | 既存の共用入力と同じ `PTX_UNSPECIFIED_SYSTEM` に変更。既存 ioctl の周波数番号から方式を判別 |
| IT930x の USB 転送用 TS 暗号化 | 実機で `bypass=0, one_word=1` を確認 | 公開 API `IT9300_setTsEncrypt(false)` と同じ順で `0xdab0 = 1`、`0xdaae = 0` を設定 |

USB 転送用の暗号化は放送の B-CAS スクランブルとは別の機能です。生 TS の一部が暗号化されたままだと adaptation field の長さも正しく読めません。BS の5秒試験では暗号化無効化前に adaptation field 不正が2572件、連続性エラーが950件あり、無効化後の8秒試験ではいずれも0件になりました。放送のスクランブルは生 TS に残っており、復号結果や APDU 成功を確認した試験ではありません。

キャプチャは `XIT-SQR100.pcapng`、978544 bytes、SHA-256 `47a3e7d2d40a730a680b345510a57ea4c975f19fd8f3147894f77ca727af0531` です。Wireshark の1始まりのフレーム番号では、REFOUT を含む書き込みは1377、2465、9945、TS 入力設定は1221、1225、1229、1541です。USB 暗号化を有効にする書き込みも2057/2061、2301/2305、9781/9785にあります。I²C bus 3、SLVT/SLVX の7-bit address `0x64` / `0x66`、tuner address `0x60` もキャプチャと一致します。

serial TS clock の設定値は次の通りです。Sony 参照実装の continuous clock の表と、Windows 選局時の書き込みを照合しています。

| 方式 | bank 0 C4[1:0] | D1[1:0] | D9 | 33[1:0] |
|---|---:|---:|---:|---:|
| ISDB-T | 2 | 2 | 16 | 0 |
| ISDB-S | 1 | 1 | 8 | 1 |

GPIO、電源待機時間、USB 転送長、再送回数、共通 TS 同期条件への変更はありません。作業開始時に存在した `it930x.c` と `xit_sqr100_device.c` の診断ログ差分は維持しています。

## ビルドと自動試験

以下は成功しました。

```sh
make -C driver
cc -std=c11 -Wall -Wextra -fsanitize=address,undefined \
  driver/tests/cxd2856er_ts_clock_test.c -o /tmp/cxd2856er_ts_clock_test_sanitized
/tmp/cxd2856er_ts_clock_test_sanitized
g++ -std=c++11 -I driver winusb/tests/ts_sync_condition_test.cpp \
  -o /tmp/sqr100-ts-sync-test
/tmp/sqr100-ts-sync-test
git diff --check
```

CXD2856ER の試験は実ソースを模擬 I²C で動かし、地デジ・衛星のキャプチャ値、PXMLT の従来値、設定対象外のビットの保持、クロック設定失敗時のエラー伝播と再開抑止を検証しています。カーネルの `vmlinux` がないため BTF 生成は省略されました。Windows x86/x64 のビルドは未実施です。

## 連続受信

実行した受信コマンドは次の形式です。標準出力を逐次解析し、ファイル保存時の滞留を挟まず受信間隔も計測しました。

```sh
recisdb tune --device /dev/sqr100video0 --channel T13 --no-decode --time 180 -
recisdb tune --device /dev/sqr100video0 --channel BS01_0 --no-decode --time 60 -
recisdb tune --device /dev/sqr100video0 --channel CS2 --no-decode --time 30 -
```

| チャンネル | 受信時間 | 完全パケット数 | 同期エラー | TEI | 連続性エラー | 形式不正 | 最大読み出し間隔 |
|---|---:|---:|---:|---:|---:|---:|---:|
| T13 | 180秒 | 3,584,770 | 0 | 3 | 0 | 1 | 46.4 ms |
| BS01_0 | 60秒 | 693,705 | 0 | 0 | 0 | 0 | 80.0 ms |
| CS2 | 30秒 | 1,040,558 | 0 | 0 | 0 | 0 | 28.1 ms |

T13 の TEI は受信開始から61、129、218番目のパケットで、形式不正は129番目に集中し、その後は増加していません。形式不正には adaptation field がパケット内に収まらない条件と予約値の adaptation field control を含めています。NULL PID は連続性計数から除外し、discontinuity indicator と同一パケットの単回再送を扱っています。recisdb の終了時に残った188 byte未満の端数は、完全パケットの計数とは別に記録しました。

この計数はアプリケーションへ届いた TS に対するもので、ドライバ内部の同期回復時に捨てられた全バイトの計数ではありません。最大読み出し間隔も USB 転送そのものの最大遅延とは異なります。復号器の D/E/S は取得しておらず、scrambled packet 数を復号失敗数として扱っていません。

## 方式切り替えと終了

同一のデバイスハンドルを開いたまま、`PTX_STOP_STREAMING`、`PTX_SET_CHANNEL`、`PTX_START_STREAMING` を使い、T13 → BS01_0 → CS2 を3周しました。各受信期間は5秒です。各周期でパーサーの端数と continuity counter を破棄し、PAT の TSID を確認しています。

| 周回 | T13 の TEI / 連続性 / 形式不正 | BS01_0 の各エラー | CS2 の各エラー |
|---|---|---|---|
| 1 | 5 / 2 / 2 | すべて0 | すべて0 |
| 2 | 1 / 1 / 0 | すべて0 | すべて0 |
| 3 | 2 / 0 / 1 | すべて0 | すべて0 |

同期エラーは全周期で0です。地デジのエラーは各周期の先頭285パケット以内で発生しました。PAT の TSID は T13 が32705、BS01_0 が16400、CS2 が24608で、別チャンネルの TSID は検出されませんでした。選局と受信開始の最大所要時間は1.1454秒、開始後の最初のデータまで最大68.34 ms、周期中の最大読み出し間隔は72.21 msです。

ロック確認まで復調器の TS 出力を止める候補と、USB ブリッジの入力を止める候補も実機で比較しましたが、いずれも開始時エラーの解消を確認できなかったため、候補の追加変更は戻しました。地デジ開始時のエラー原因は未確定です。

受信後のデバイス参照は回収され、`/sys/module/px4_drv/refcnt` は0へ戻りました。モジュール読み込み後の再オープンも確認しています。最終ソースの再読み込み後の T13 30秒受信も成功しましたが、開始直後の368パケット以内に TEI が6件、形式不正が2件あり、その後は増えていません。PX-MLT8PE の未使用チューナーで T13 の比較受信を試みましたが、選局が errno 125 で失敗したため、同機種の受信回帰試験には至っていません。

## 残る確認範囲と適用状態

地デジ開始時のエラー、数時間〜数日の連続受信、実際の USB 抜去・再接続、コールド起動、アンテナ未接続時、全チャンネル、別ロット、外付けカードリーダー、内蔵カードの APDU、複数機器の同時受信は未確認です。GPIO の信号名・極性の独立した検証も残っています。

修正モジュールは `insmod` で実機に読み込まれています。インストール済みの DKMS パッケージは `px4_drv/0.5.5` のままで、永続インストールは未実施です。再起動や既存 DKMS モジュールの読み込みでは、今回の修正が適用されない場合があります。
